# Skill books and work progression

Version 0.14.0 contract. Target: the current Steam release selected by the user. These are additional supported mechanics, not a parity claim.

## Reference evidence

The developer's [Steam announcement archive](https://store.steampowered.com/news/posts/?appgroupname=Pixel+Piracy&appids=264140&enddate=1683280598&feed=steam_community_announcements), patch 1.2.22 on March 31, 2023, describes clicking pirate skills to level them with matching books. It supports book-based ranks in the revived PC game. Historical [skills guidance](https://pixelpiracy.fandom.com/wiki/Skills) describes training-point costs; dated guides disagree about those amounts. The [2016 review](https://www.mygamer.com/pixel-piracy-review/) describes experience from basic jobs. These establish categories, not current numerical balance. The installed current Steam build, complete skill catalogue, caps, individual prices, point costs and rank effects remain unmeasured.

## Authored bounded rules

Eight existing browser skills each have ranks zero through five: zero means unlearned, one preserves the previous effect. Learned skills remain an explicit, unique list for duty compatibility. New starters keep their existing free rank-one skills. Every subsequent learning or rank increase costs one matching book and one earned training point. Books can be purchased into the shared hold for 60 gold, sold only from owned stock for 30 gold, or bought and read immediately from the inspector. Reading consumes an owned book before charging gold. Each of eight stacks caps at 99. No book drops or stock are silently granted. The ship’s hold lists owned books and opens the selected pirate’s inspector for reading; empty stocks show guidance. Original integer-pixel book icons reuse the inventory style.

Learning a work skill assigns its duty and interrupts current work/orders as before. Learning Swimming leaves the duty unchanged. Upgrading a known skill preserves duty, orders, work progress and claims. All market and reading operations require port; recipients must be living allies. Known-skill learning, unknown-skill upgrades, capped ranks, missing points/books/gold, invalid keys and unsafe phases reject before resource mutation. Point accounting includes attribute spends, remaining points and lifetime book point spends; saves reject totals above four times level.

Guard adds one derived attack damage per rank above one. Cook, clean, repair, medicine, cannon and fishing add 20% work rate per rank above one; outputs and input costs are unchanged. Swimming increases swimming and rail-climb rate by 20% per rank above one, while rescue hauling retains its independent rate. Ranks do not alter weapon animation/grip geometry or saved base damage. These formulas, prices and caps are authored provisional balance.

A completed station job awards two XP through the existing intelligence/level helper. Partial work, cancelled jobs, unavailable resources, idle duty and merely walking to a station award none. Awards occur once after work output, and the existing maximum level blocks further XP gains. Work time, low morale and Industrious compose deterministically at 20 Hz using integer progress units (80 per baseline tick). This avoids floating-point drift: a rank-four 1.6-rate repair finishes exactly on tick 50, rather than slipping to tick 51. A regression first reproduced the late resource/output/XP boundary, then passes with integer accumulation. No timer, event history, skill-specific XP pool or per-frame world copy is added.

## Persistence and transactions

Schema 10 adds eight exact skill-rank keys, integer lifetime `skillPointsSpent` (0–40), and eight exact book-stock keys. Learned ranks must be 1–5; unknown ranks must be exactly zero. Lifetime spends must cover added ranks and cannot exceed total ranks. All fields are explicitly copied. Schema-nine migration is immutable, bounds collections before mapping, assigns rank one to prior learned skills and zero elsewhere, empty book stock and zero book spends. Existing attributes, points, injuries, damage, XP, groups, gear, map and other inventory are preserved; migration grants and consumes no points. Older saves pass through the prior chain.

Reading, buying and selling use the same awaited checkpoint transaction as equipment. A failed write restores the entire pre-action campaign and selection, including books, points, ranks and gold. No new storage owner or queue is added.

## Input and resource ownership

Canvas targeting reads existing rendered bodies at click time, following interpolation, jumps and sea traversal. Dead actors, absent/inactive/hidden bodies and submerged cropped lower bodies cannot receive a hit. Overlapping visible bodies use actual display-list order, including a captain recreated after rollback. Existing scene owners, input subscriptions, actor maps and disposal remain; the bounded scan allocates no candidate array or rectangle cache. At most 24 bodies are inspected. The accepted art and native dimensions remain unchanged.
